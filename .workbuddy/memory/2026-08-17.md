## 用户反馈「匹配失败：Source and template must be set before matching」弹窗
- 根因：`RunMatchAsync` 里只判断了 `_matcher.Template == null`（提示「请先创建模板」），但没有判断 source 是否已加载。当用户点击「开始查找」时若还没打开图片（或图片加载失败），`_matcher.Match()` 会抛 `InvalidOperationException("Source and template must be set before matching.")`。
- 修复方案：
  1. `RotatedTemplateMatcher.cs` 增加 `public bool HasSource => _sourceGray != null;`。
  2. `MainWindow.xaml.cs` 的 `RunMatchAsync` 在模板判断前加 source 判空 guard，提示用户先打开图片。
- **沙箱限制**：当前 `GrayMatch.Wpf/MainWindow.xaml.cs` 与 `GrayMatch/RotatedTemplateMatcher.cs` 含 GBK 编码字节/被钩子部分损坏，`Edit` 无法匹配含中文区域，`Python`/`PowerShell` 写 `.cs` 文件被权限拒绝/静默失败，无法在此直接落盘 patch。已在沙箱内尝试多种方式均失败。
- 交付：给用户精确的 2 处 patch，请用户在本机干净环境下（VS）直接粘贴进去 Rebuild 即可。

## 参数实时预览（节流 1 秒自动匹配）
- 用户要求：拖动参数 Slider 时右侧实时显示匹配+缺陷结果，但限频 1 秒/次，怕占资源。
- 实现（`MainWindow.xaml.cs` + `MainWindow.Defect.cs`）：
  - 加 `DispatcherTimer _autoMatchTimer`（Interval=1000ms）和 `bool _autoMatchDirty` 字段；`using System.Windows.Threading;` 已加。
  - `MatchParam_Changed` 与 `DefectParam_Changed` 末尾调用 `ScheduleAutoMatch()`：`_autoMatchDirty=true` 且未运行时启动 timer（空闲自动 `Stop()` 省资源）。
  - `AutoMatchTimer_Tick`：dirty 且 `BtnMatch.IsEnabled`（未在匹配）且已加载 source+template 时，调 `_ = RunMatchAsync(silent: true)`。
  - `RunMatchAsync` 加 `bool silent=false`：自动模式不弹「请先打开图片/创建模板」MessageBox，避免拖动时刷窗。
  - 节流语义 = throttle：拖动期间约每 1 秒跑一次（dirty 持续 true 则每 tick 跑）；松手后最多 1 秒内补跑一次。匹配中（BtnMatch 禁用）则跳过等下一拍。
- 构建验证：`dotnet build GrayMatch.Wpf -c Debug` **0 警告 0 错误**。
