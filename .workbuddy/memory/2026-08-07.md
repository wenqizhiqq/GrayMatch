## 第二轮：WPF 重写 + 角度 Bug 修复 + 30ms 提速
- 用户发现 WinForms 缩放后鼠标坐标错位 + 匹配结果显示角度不对（如直立目标显示 116°）。

- **修复**：粗扫只负责定位（5°→15° 步长），精修在种子位置 `±25°` 内重新搜索真实角度，找不到则 fallback 全范围。

- **30ms 提速**（测试图 600×900，模板 120×80）：
  - 粗扫 0.25x 图 + 15° 步长 + 阈值 max(0.15, thr-0.2)
  - 精修 0.35x 窗口 + 强制步长 ≥2° + 种子 OpenMP 并行 + 小窗口（margin=max(tpl)×0.75+8）
  - 旋转模板缓存（每角度只 warpAffine 一次）
  - Benchmark（-180..180, step1）从 746ms → **32ms**，4/4 目标；Can_Detect 34ms/4。
- **WPF 踩坑**：同时满足 `UseWindowsForms=true` 与 `OpenCvSharp` 会令 `Point/Window/MouseEventArgs` 歧义。已移除 WinForms，新增 `OpenCvSharp4.Extensions`；`Mat.ToBitmapSource()` 在该版本未生效，改用 `mat.ImEncode(".png")` → MemoryStream → `BitmapImage`。

## 第三轮：绿色框大小/角度画错（渲染层 Bug）
- 现象：WPF 中角度文字（Angle 值）正确，但绿色框「大小+角度」都不对。
- **根因**：native `matchAtLevel` 把每个结果的 `templateWidth/Height` 设成**旋转后模板的包围盒尺寸**（`rotated.cols/rows`，随角度变大，如 30° 时 120×80→144×129），并把 `leftTopX/Y` 设成该旋转包围盒左上角。WPF 按这两个值画矩形 → 框比目标大、形状不同，视觉上角度也歪。
- **修复**：在 `match()` 返回前**统一覆写**每个结果为**原始未旋转模板尺寸**（`templateGray_.cols/rows`）且 `leftTopX/Y = center - 原始/2`，使绿色框 = 原始模板矩形、以检测中心为心、按 Angle 旋转，正好贴合目标。WPF 端 `RenderTransformOrigin="0.5,0.5"` + `RotateTransform Angle={Binding Angle}` 无需改。
- **致命坑（已实证的回归）**：覆写前**必须保留** Pass-2 映射循环里对 `r.leftTopX/Y` 的赋值（`r.leftTopX = round(centerX - r.templateWidth/2)`）。一旦删掉该赋值，检测数会从 4 塌成 1（仅剩 0° 目标）。原因未完全厘清（NMS 用的是覆写前的中间 box 值），但**两处 leftTop 赋值同时存在**是稳定通过的组合。
- **fineScale 下限**：0.35 是底线。降到 0.33 会让旋转模板在低分辨率下双线性插值失真，细扫 NCC 低于 0.35 阈值 → 旋转目标漏检（再次塌成 1）。不要低于 0.35。
- 测试加固：给 `Can_Detect` 增加断言——角度 ±2.5°、模板尺寸==原始(120×80)、框中心==检测中心(误差≤1px)。确保框几何回归可被发现。
- **最终验证**：Can_Detect 32ms/4、Benchmark 33ms/4（全 360°），3 测试全 PASS；WPF 0 警告 0 错误。
- 结论：耗时为 32–33ms（接近 30ms 目标）。用户真实大图(18 目标)曾 137ms，要压到 30ms 需再降分辨率（有漏检风险），故保留保真度。

## 第四轮：耗时只算匹配 + 绿色框角度反了
- 用户要求：① 计算耗时只算「匹配」本身，不要算创建模板（warpAffine 旋转模板缓存）和绘画；② 绿色结果框角度画反了。
- **耗时范围修复（native）**：原 `match()` 把「旋转模板缓存构建」也算进计时。改为——在计时器启动前**预预热** coarseCache 与 fineCache（遍历角度 warp 一遍），计时区间 = `tMatch→tEnd` 减去 `tAfterPass1→tFineBuild`（fine 缓存构建段），即 `lastMatchMs_ = ms(tMatch,tEnd) - ms(tAfterPass1,tFineBuild)`，得到「纯匹配」耗时。新增 `mutable double lastMatchMs_` + `public double lastMatchMs() const` getter。
- **C2248 编译坑**：`gm_get_last_match_ms` 最初直接读 private `lastMatchMs_`，编译失败。修正：加 public getter `lastMatchMs()`，extern 函数改调 `m->lastMatchMs()`；并因 `match()` 是 `const` 方法需写成员，故成员加 `mutable`。
- **绿色框角度反了（根因 = 旋转约定相反）**：OpenCV `getRotationMatrix2D` 正角度 = **逆时针**（屏幕），WPF `RotateTransform` 正角度 = **顺时针**，二者相反。故 WPF 画框须用**取反角度**才与图像里 OpenCV 绘制的真实目标对齐。
- **修复**：新增 `AngleSignConverter : IValueConverter`（Convert 返回 `-d`），在 XAML 声明 `<local:AngleSignConverter x:Key="AngleNegate"/>`，把结果框 `<RotateTransform Angle="{Binding Angle, Converter={StaticResource AngleNegate}}"/>` 改为取反；角度**文字**仍绑原始 `Angle`（保持真实值）。`MainWindow.xaml.cs` 状态栏改读 `_matcher.LastMatchMs`（纯匹配耗时），移除 Stopwatch；`RotatedTemplateMatcher.cs` 增 `LastMatchMs` 属性 + `gm_get_last_match_ms` P/Invoke。
- **最终验证**：3 测试全 PASS；`Can_Detect` 纯匹配 12.8ms/4，`Benchmark` 全 360° 纯匹配 33.8ms/4（均不含模板缓存构建）；WPF 0 警告 0 错误；WinForms 项目也 0 警告 0 错误。框几何断言（原始尺寸 + 中心对齐）仍过。
- **构建注意**：`dotnet test` 偶发 CS2012 写锁（GrayMatch.dll 被 VBCSCompiler 持锁）。先 `dotnet build-server shutdown` 关掉 MSBuild/VB-C# 编译器服务器再建即可。
