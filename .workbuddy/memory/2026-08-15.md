## 图片切换卡顿根因分析（GrayMatch）
- 用户问「切换图片为什么卡，是不是和模板耦合」。确认：**是**，且强耦合。
- 根因 1（主因）：`LstImages_SelectionChanged` 在载入图片后自动 `RunMatchAsync` → `_matcher.Match(...)`，默认 360° 全扫。且 native `Match()` 每次都 `gm_create()+gm_set_template()`，**模板旋转缓存每次匹配都从头重建**；切 N 张图=重建 N 次。这就是「和模板耦合」的来源。
- 根因 2（次因）：`RefreshDisplayBitmap()` 每次载入 + 每次匹配后都逐行 Marshal.Copy 整张彩色图重建 WriteableBitmap（大图更慢），no-defect 分支匹配后还多余重拷一遍。
- 好消息：`DisposeSource()` 只清 `_source/_sourceGray`，不动 `_template`，切图不会丢模板。

## 修复方案（用户选「切换只加载不自动匹配」）
- 改动 1：`LstImages_SelectionChanged` 删掉自动 `RunMatchAsync` 调用，切图只 `LoadSourceFromPathAsync`（载入+显示）。匹配改由「开始查找」按钮触发。切图与模板彻底解耦 → 切图毫秒级。

## 2026-08-15 续：修复 `Cv2.CvtColor` 空图异常（`!src.empty()`）
- 用户截图：`RotatedTemplateMatcher.LoadSource(path)` 中 `Cv2.ImRead` 返回空 Mat，随后 `CvtColor` 抛 `OpenCvSharp.OpenCVException: "!src.empty()"`。
- 根因：`LoadSource` 没有校验 ImRead 结果，某些情况下（文件被删/损坏/格式不支持/路径含特殊字符/文件被占用）会直接崩溃。
- 修复：
  - `RotatedTemplateMatcher.LoadSource` 加 `string.IsNullOrWhiteSpace` 与 `File.Exists` 前置检查；ImRead 后检查 `_source == null || _source.Empty()`，失败抛带完整路径的 `InvalidOperationException`。
  - 补 `using System.IO;`。
  - `MainWindow.LoadSourceFromPathAsync` catch 块新增非 `OperationCanceledException` 的通用处理，把异常消息写到 `StatusText`，避免未处理异常弹窗。
- 构建结果：`dotnet build GrayMatch.Wpf -c Debug` **0 警告 0 错误**。
- 用户可确认具体哪张图读不出：状态栏会显示「载入失败：无法读取图片：X:\\...」。常见原因包括文件被其他程序锁定、图片头损坏、或扩展名与实际格式不符。

## 绿色轮廓线「不显示」的根因与修复（2026-08-15 晚）
- 用户实测：勾选轮廓匹配后绿框出现，但绿色轮廓线条不显示。
- 根因：旧实现把绿色轮廓「烤」进 `SourceBitmap`（图像像素），与匹配结果绿框（XAML `ItemsControl` 叠加层）是**两套坐标系/刷新时机**，且 Canny 阈值偏高(40,120)可能得到空掩码 → 多条原因叠加导致不显示。
- 修复：改为**让绿色轮廓与绿框共用同一 XAML 叠加层坐标系**。
  - `MainWindow` 新增 `TemplateContourOverlay`（BGRA 小图：透明底+绿线，模板尺寸），`BuildContourOverlay()` 由 `_templateContourMask` 生成并 `Freeze()`。
  - `Results` 的 `ItemTemplate` 内新增 `<Image>`：`Width/Height=TemplateWidth/Height`、`Stretch=Fill`、与绿框同样 `RenderTransformOrigin=0.5,0.5` + `RotateTransform Angle={Binding Angle, Converter=AngleNegate}`、`Source` 绑定 `RelativeSource AncestorType=Window, Path=TemplateContourOverlay`。这样轮廓严格对齐绿框、且随绿框一起缩放/显示。
  - `TemplateContourOverlay` 在以下时机赋值：创建模板时（仅轮廓模式开才建）、`ChkContour_Changed` 切换时（开→建、关→null）、`LoadPersistedStateAsync` 载入持久化模板时。属性变化经 INPC 即时刷新，已有匹配结果也会实时出现/消失绿线。
  - 移除 `RefreshDisplayBitmap` 里烤进位图的绿色块及其 `contourResults` 参数、删除 `_paintedContour` 字段，避免双重绘制与坐标错乱。
- `ComputeTemplateContourMask` 增强鲁棒性：Canny 阈值降到 (20,60)；若边缘像素 <5（低对比模板）回退用 Sobel 梯度幅度阈值 `0.25*max` 作为边缘，保证轮廓线至少有可见的模板形状。
- 构建结果：`dotnet build GrayMatch.Wpf -c Debug` **0 警告 0 错误**。

## 模板实时显示绿色轮廓 + 轮廓匹配参数面板（2026-08-15 晚，续上）
- 用户要求：①画模板且勾选轮廓匹配时，左侧模板预览要显示模板的绿色轮廓；②加轮廓匹配参数；③调参时绿色轮廓实时刷新到模板图片。
- `RotatedTemplateMatcher` 新增两个可调参数并接入掩码/梯度生成：
  - `ContourThreshold`（int 1-254，默认 30）：Canny 低阈值，越大保留边越少。
  - `ContourBlur`（double 0-12，默认 1）：高斯预模糊 sigma，也作用于**匹配用的梯度图**（影响匹配），0=不模糊。
  - `ComputeTemplateContourMask()` 现在先按 `ContourBlur` 高斯模糊，再用 `ContourThreshold`/`×2` 做 Canny；边缘 <5 时仍回退 Sobel 幅度阈值。
  - `MakeContour()` 改为实例方法，先按 `ContourBlur` 模糊再做 Sobel 幅度归一化（喂 native 的梯度图受平滑影响）。
  - 新增 `RecomputeContours()`：重算模板边缘掩码 +（轮廓模式开时）重建 source/template 梯度图；模板级开销可忽略。
- UI：
  - XAML 在 `ChkContour` 下方加参数 `Border`（`IsEnabled` 绑定 `ChkContour.IsChecked`）：「平滑」`TbContourBlur`（默认 1）、「轮廓阈值」`TbContourThreshold`（默认 30），并提示「调参时左侧模板会实时显示绿色轮廓」。
  - `MainWindow` 新增 `BuildTemplateContourPreview()`（灰度底 + 绿线，Bgr24，用于左侧预览）与 `RefreshTemplateVisuals()`（轮廓开→`TemplateBitmap=BuildTemplateContourPreview()` 且重建 `TemplateContourOverlay`；关→只显示灰度模板）。
  - `StartCreateTemplate` / `ChkContour_Changed` / `LoadPersistedStateAsync` 统一改用 `RefreshTemplateVisuals()`；`ChkContour_Changed` 切状态时先 `_matcher.RecomputeContours()`。
  - 新增 `ContourParam_Changed`：解析两个 TextBox → 写入 matcher → `RecomputeContours()` → `RefreshTemplateVisuals()`（仅轮廓开且已有模板时），实现调参实时刷新左侧绿色轮廓。
