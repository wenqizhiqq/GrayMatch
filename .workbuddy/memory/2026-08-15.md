## 图片切换卡顿根因分析（GrayMatch）
- 用户问「切换图片为什么卡，是不是和模板耦合」。确认：**是**，且强耦合。
- 根因 1（主因）：`LstImages_SelectionChanged` 在载入图片后自动 `RunMatchAsync` → `_matcher.Match(...)`，默认 360° 全扫。且 native `Match()` 每次都 `gm_create()+gm_set_template()`，**模板旋转缓存每次匹配都从头重建**；切 N 张图=重建 N 次。这就是「和模板耦合」的来源。
- 根因 2（次因）：`RefreshDisplayBitmap()` 每次载入 + 每次匹配后都逐行 Marshal.Copy 整张彩色图重建 WriteableBitmap（大图更慢），no-defect 分支匹配后还多余重拷一遍。
- 好消息：`DisposeSource()` 只清 `_source/_sourceGray`，不动 `_template`，切图不会丢模板。

## 修复方案（用户选「切换只加载不自动匹配」）
- 改动 1：`LstImages_SelectionChanged` 删掉自动 `RunMatchAsync` 调用，切图只 `LoadSourceFromPathAsync`（载入+显示）。匹配改由「开始查找」按钮触发。切图与模板彻底解耦 → 切图毫秒级。
- 改动 2：`RunMatchAsync` no-defect 分支去掉多余的 `RefreshDisplayBitmap()`；用 `_paintedRed` 标记，仅上一轮画过红、本轮没画时才重绘清红。

## 2026-08-15 续：修复 `Cv2.CvtColor` 空图异常（`!src.empty()`）
- 用户截图：`RotatedTemplateMatcher.LoadSource(path)` 中 `Cv2.ImRead` 返回空 Mat，随后 `CvtColor` 抛 `OpenCvSharp.OpenCVException: "!src.empty()"`。
- 根因：`LoadSource` 没有校验 ImRead 结果，某些情况下（文件被删/损坏/格式不支持/路径含特殊字符/文件被占用）会直接崩溃。
- 修复：
  - `RotatedTemplateMatcher.LoadSource` 加 `string.IsNullOrWhiteSpace` 与 `File.Exists` 前置检查；ImRead 后检查 `_source == null || _source.Empty()`，失败抛带完整路径的 `InvalidOperationException`。
  - 补 `using System.IO;`。
  - `MainWindow.LoadSourceFromPathAsync` catch 块新增非 `OperationCanceledException` 的通用处理，把异常消息写到 `StatusText`，避免未处理异常弹窗。
- 构建结果：`dotnet build GrayMatch.Wpf -c Debug` **0 警告 0 错误**。
- 用户可确认具体哪张图读不出：状态栏会显示「载入失败：无法读取图片：X:\\...」。常见原因包括文件被其他程序锁定、图片头损坏、或扩展名与实际格式不符。

## 2026-08-15 续：修复 `Template not created` 异常
- 用户截图：`System.InvalidOperationException: "Template not created."` 在 `RotatedTemplateMatcher.Template` getter 行 13 触发。
- 根因：`Template` getter 设计为 `_template` 为 null 时抛异常；但 UI 多处用 `if (_matcher.Template != null)` / `== null` 做存在性判断，而 `!= null` / `== null` 会先调用 getter，于是 null 时直接爆炸。
- 修复：`Template` getter 改为 `public Mat? Template => _template;`（允许可空返回，不再抛异常）。`Match` 方法内部仍保留 `_template == null` 检查并抛友好提示；UI 判断语句因此能正常工作。
- 构建结果：`dotnet build GrayMatch.Wpf -c Debug` **0 警告 0 错误**。
