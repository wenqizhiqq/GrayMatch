## NoCodeVision RoiImageView：中键缩放/平移确认修复 + 复位不居中根因修复
- 用户确认：上回合把滚轮缩放+中键平移改挂到 UserControl Preview 级后，**中键缩放/拖动已正常**。
- 新问题：「复位（右下角按钮）不居中、不最大化」。
- 排查：FitView 数学（min 比例适配 + (avail-size*s)/2 居中）本身正确；宿主布局有界（VisionToolView Grid 格 / FlowView 在 Height=300 的 Border 里）。
- 根因（唯一能解释"缩放平移正常、唯独复位大小/居中不对"的机制）：**图片自带 DPI 元数据**。
  WPF `Stretch=None` 按物理尺寸渲染：DIP = PixelWidth × 96 / DpiX。72/144/200 DPI 的图
  （截图、微信传图、相机图常见）实际渲染尺寸 ≠ PixelWidth，而 FitView 全按 PixelWidth 算
  → 复位后图偏大（溢出裁切）或偏小（不满），居中偏移也错。缩放/平移跟着实际变换走所以正常。
- 修复（`Views/Controls/RoiImageView.xaml(.cs)`）：
  1. `Img`/`DefectLayer` XAML 改 `Stretch="Fill"` + 代码里显式 `Width/Height = PixelWidth/Height`
     （1 像素 = 1 DIP，抵消 DPI；96 DPI 图零变化，非 96 DPI 图与适配数学严格一致）。
  2. `OnSourceChanged` 的类型判断从 `BitmapImage` 放宽到 `BitmapSource`（兼容 WriteableBitmap 等）。
  3. `OnDefectOverlayChanged` 同样按缺陷图自身像素钉 DefectLayer 尺寸，保证与底图对齐。
  4. `OnFitViewClick` 防御：清 `_panDragging`、释放 Root 残留鼠标捕获（防复位点击被吞）、
     布局尺寸为 0 时 Dispatcher(Loaded) 补一次 FitView。
- 构建：`dotnet build NoCodeVision.csproj -c Debug` → 0 错误（32 警告全为项目原有，与本次无关）。
- 待用户重编译验证：任意 DPI 的图复位后应居中 + 最大化铺满。
- 备注：上一回合用户曾要求"中键拖动缩放"，追问平移安置方案未答；实际用户对现状
  （滚轮=缩放、中键拖=平移）已满意，未再改交互。

## 中键缩放/平移整体重写（用户："你重新写一个鼠标中键缩放拖动功能"）
- 把 `RoiImageView` 的视图变换逻辑推倒重写为单一 `#region 视图变换`，XAML 事件名不变（零 XAML 改动）：
  - 统一入口 `ApplyTransform(scale, tx, ty)`：scale/translate 永远一起写，不出半新半旧状态。
  - `ScreenToImage(p)`（原 ViewportToImage）：对 screen = scale*local + translate 求逆，
    注释明确"不要用 GetPosition(PixelCanvas)，LayoutTransform 元素上不可靠"。
  - `UpdateFit()`：按 Root 尺寸重算 _fitScale；`_userTransformed`=false 时自动 FitToView，
    true 时只刷新比例保留用户视图（原 UpdateScale/_manualTransform 改名）。
  - `FitToView()`（原 FitView）：适配 + 居中。
  - 滚轮缩放：ZoomStep=1.2（原 1.12），_zoomFactor 夹 0.5~10，到边界不再空转；光标锚定不变。
  - 中键拖动平移：按下记 _panOrigin/_panBaseX/Y + Root.CaptureMouse，Move 累加，Up 释放捕获。
  - 复位按钮：清 _userTransformed/_panning、释放捕获、FitToView；布局未就绪时 Dispatcher(Loaded) 补一次。
  - 删除了文件后部旧的重复 pan 区（引用已删字段，不删必编译错）。
- 交互约定保持：滚轮=以光标为锚点缩放、中键拖=平移、左键=画框/测量、右下按钮=复位。
- 构建：`dotnet build NoCodeVision.csproj -c Debug` → 0 错误（32 警告全为项目原有）。
