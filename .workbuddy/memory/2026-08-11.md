# 2026-08-11

## 灰度匹配 GPU 加速（2026-08-11）
- 目标：给 GrayModelNative 加 GPU 加速。预编译 `opencv_world480` 已 `HAVE_OPENCL`，但**无 CUDA**（cvconfig 显示 `/* #undef HAVE_CUDA */`）。
- 方案：OpenCV Transparent API（UMat→OpenCL）。把 `rotateImage/TemplateCache/matchAtLevel` 模板化（cv::Mat|cv::UMat），`match()` 按 `useGpu_ && cv::ocl::haveOpenCL()` 调度，异常自动回退 CPU。新增 C API `gm_set_gpu` / `gm_get_gpu_info`（返回设备名+是否GPU）。
- 编译：`cl /std:c++17 /O2 /EHsc /openmp /utf-8 /LD /DGRAYMODEL_EXPORTS`（注意 `cl` 生成的 import lib 名为 `gray_model_native.lib`，需 `/IMPLIB:build-ninja7/GrayModelNative.lib` 覆盖 cmake 旧 lib 否则链接不到新符号）。
- **关键结论（实测，沙箱有 Intel Arc 140T GPU + OpenCL）**：逐角度 `matchTemplate` 在 GPU 上**反而慢 30~480×**（pyr0: 2411ms vs 5ms；pyr4: 31ms vs 1ms）。根因：本算法每角度一次 `matchTemplate`，OpenCL 单次调用有 ~30ms 固定开销（kernel 派发 + `getMat` 回读同步），对小模板/多角度场景完全压不住房算量。
- 因此 GPU 路径**保留但默认关闭**，WPF 左侧加「使用 GPU 加速 (OpenCL)」勾选框（默认不勾）+ 提示“实验性，可能更慢”，电脑配置里显示 `GPU (OpenCL): ...`。
- 真正提速需**批量角度**自定义 OpenCL/CUDA kernel（一次派发算多角），或重编 OpenCV 带 CUDA 用 `cv::cuda::matchTemplate`。当前最快仍是 CPU + OpenMP + 金字塔。
- 文件改动：`GrayModelNative/gray_model_native.cpp`(模板化+GPU 调度)、`gray_model_native.h`(新 API)、`GrayMatch/RotatedTemplateMatcher.cs`(`GpuEnabled`+`GetGpuInfo`+P/Invoke)、`GrayMatch.Wpf/MainWindow.xaml(.cs)`(勾选框+配置显示)。WPF 用 `dotnet build -p:UseSharedCompilation=false` 绕过 VBCSCompiler 锁。

## 缺陷检测（2026-08-11，叠加在匹配之上）
- 需求：匹配同时做缺陷检测，红色半透明标注 + 红色文字标注缺陷类型。检测依据=与模板比对找异常；四类全做：污渍/异物(暗斑)、划痕(亮/暗线)、缺料/破损(缺失区)、亮度/对比度异常。
- 实现位置：**C#/WPF 用 OpenCvSharp**（不碰原生 DLL，改动局部易调试）。新增 `GrayMatch/DefectResult.cs`；`RotatedTemplateMatcher.DetectDefects(List<MatchResult>)`：
  - 对每个匹配：用 `GetRotationMatrix2D(center,-angle)` 逆旋转源图使实例 upright、与 upright 模板对齐；`GetRectSubPix` 取 tw×th patch；`Absdiff` 差值图；`Threshold` 异常掩码；`FindContours`+`ContourArea` 过滤；按轮廓内 `Mean(patch)-Mean(template)` 判明暗、按 `MinAreaRect` 纵横比判细长(划痕)、按面积占比判缺料/破损；无局部缺陷但整体均值差大→亮度/对比度异常。
  - 每个缺陷存 upright 模板局部 bbox(X,Y,W,H) + 预计算图像空间中心(`ImgCx/ImgCy`，用**与匹配框相同的 -angle 变换**，约定无关) + `TextLeft/TextTop`(给文字用)。
- WPF：`MainWindow.xaml` 加「检测缺陷（模板比对）」勾选框 + 缺陷叠加层 `ItemsControl`(红色半透明 Rectangle 旋转 -angle + 红色文字 Type) + 左侧「缺陷统计」(`DefectSummaryText`)；`MainWindow.xaml.cs` 加 `Defects` 集合、`DefectSummaryText`、`ChkDefect_Changed`、`BuildDefectSummary`，RunMatchAsync 内 `_defectEnabled` 时调 `DetectDefects`；**`GrayMatch.Wpf.csproj` 须显式 `<Compile Include=..\GrayMatch\DefectResult.cs>`**（WPF 只 link 了 MatchResult/RotatedTemplateMatcher，不自动含新文件，否则 wpftmp 报 CS0246）。
- **跨版本坑**：WPF 用 OpenCvSharp 4.8.0，`InterpolationFlags.InterLinear` 不存在(4.8 叫 `Linear`，4.13 叫 `InterLinear`)。同一 RotatedTemplateMatcher.cs 被 GrayMatch(4.13) 与 WPF(4.8) 两项目编译，故用 `(InterpolationFlags)1`(INTER_LINEAR=1) 强制转换，两版本通用。
- 验证：沙箱无头跑不了 GUI。另建 `C:\gmrun5\defect_test` 控制台(只 link 三个 .cs，不调原生)注入合成暗斑+亮线到旋转 30° 模板实例，`DetectDefects` 正确回报 `污渍/异物 @(216.9,198.3)` 与 `划痕 @(190.7,205.9)`，位置与注入点吻合。
- 构建：`dotnet build GrayMatch.slnx -p:UseSharedCompilation=false` → 0 警告 0 错误。
