## 灰度匹配 GPU 加速（2026-08-11）
- 目标：给 GrayModelNative 加 GPU 加速。预编译 `opencv_world480` 已 `HAVE_OPENCL`，但**无 CUDA**（cvconfig 显示 `/* #undef HAVE_CUDA */`）。
- 方案：OpenCV Transparent API（UMat→OpenCL）。把 `rotateImage/TemplateCache/matchAtLevel` 模板化（cv::Mat|cv::UMat），`match()` 按 `useGpu_ && cv::ocl::haveOpenCL()` 调度，异常自动回退 CPU。新增 C API `gm_set_gpu` / `gm_get_gpu_info`（返回设备名+是否GPU）。
- 编译：`cl /std:c++17 /O2 /EHsc /openmp /utf-8 /LD /DGRAYMODEL_EXPORTS`（注意 `cl` 生成的 import lib 名为 `gray_model_native.lib`，需 `/IMPLIB:build-ninja7/GrayModelNative.lib` 覆盖 cmake 旧 lib 否则链接不到新符号）。
- **关键结论（实测，沙箱有 Intel Arc 140T GPU + OpenCL）**：逐角度 `matchTemplate` 在 GPU 上**反而慢 30~480×**（pyr0: 2411ms vs 5ms；pyr4: 31ms vs 1ms）。根因：本算法每角度一次 `matchTemplate`，OpenCL 单次调用有 ~30ms 固定开销（kernel 派发 + `getMat` 回读同步），对小模板/多角度场景完全压不住房算量。
- 因此 GPU 路径**保留但默认关闭**，WPF 左侧加「使用 GPU 加速 (OpenCL)」勾选框（默认不勾）+ 提示“实验性，可能更慢”，电脑配置里显示 `GPU (OpenCL): ...`。
- 真正提速需**批量角度**自定义 OpenCL/CUDA kernel（一次派发算多角），或重编 OpenCV 带 CUDA 用 `cv::cuda::matchTemplate`。当前最快仍是 CPU + OpenMP + 金字塔。
- 文件改动：`GrayModelNative/gray_model_native.cpp`(模板化+GPU 调度)、`gray_model_native.h`(新 API)、`GrayMatch/RotatedTemplateMatcher.cs`(`GpuEnabled`+`GetGpuInfo`+P/Invoke)、`GrayMatch.Wpf/MainWindow.xaml(.cs)`(勾选框+配置显示)。WPF 用 `dotnet build -p:UseSharedCompilation=false` 绕过 VBCSCompiler 锁。

## WPF 图像查看器 fit-to-view 修复（用户："下半部分图片没有显示"）
- 症状：换成变换式缩放后，大图只显示左上角、下半部分被 `ClipToBounds` 裁掉。根因：`FitToView()` 在 `ImageGrid` 还没量出真实尺寸（图像未加载、`ActualWidth` 仍为 0）时提前 return，缩放停在默认 1:1、平移 0 → 原生尺寸左上角对齐，被裁。窗口 Loaded / 首次 SizeChanged 都早于图像就绪，所以之后再没触发适配。
- 修复：给 `ImageGrid` 加 `SizeChanged="ImageGrid_SizeChanged"`（RenderTransform 不影响布局，故该事件只在图像尺寸变化时触发，是最可靠的适配时机）；`OnSourceImageChanged` 载入新图时复位 `_manualTransform=false` 并 `BeginInvoke` 适配。双保险：viewport 与 grid 的 SizeChanged 在「未手动变换」时都会重拟合。
- 操作不变：滚轮缩放 / 中键平移 / 左键双击复位。构建 **0 警告 0 错误**（`_wpfout10`）。
- **第二轮（截图显示 fit 已执行、缩放 0.715、但仍缺底部）**：`FitToView` 已跑（状态栏 `适配#5 缩放=0.715 图=1339x1038 视口=1367x743`），但画面仍像 1:1 被裁。根因修正：`ImageGrid` 原绑定 `Width/Height=ImageWidth/ImageHeight`（像素尺寸），而 WPF `Image.Stretch=None` 按源图像 DPI 显示，DPI≠96 时实际 DIP 尺寸会大于 Grid，内容溢出被 `ClipToBounds` 裁掉。
- **修复（`_wpfout14`）**：去掉 `ImageGrid` 的显式 `Width/Height` 绑定，让它随 `Image` 内容自动尺寸；`FitToView` 继续用 `ImageGrid.ActualWidth/Height`，现在它等同于实际显示尺寸。保留 `SourceBitmap` PropertyChanged、`LayoutUpdated`、`SizeChanged` 多重触发器，状态栏仍显示诊断信息。
- 注意：默认 `bin` 被锁定无法覆盖，运行请用 `_wpfout14\\Debug\\net8.0-windows\\GrayMatch.Wpf.exe`。
- **第三轮（截图显示网格=视口=1383x743，缩放=1.0，仍缺底部）**：去掉 `Width/Height` 绑定后 `ImageGrid` 没有随 `Image` 内容撑开，反而被压成视口大小。根因仍待确认（可能是 overlay Canvas/ItemsControl 意外撑开或父容器约束）。
- **修复（`_wpfout15`）**：在 `OnSourceImageChanged` 里直接把 `ImageGrid.Width/Height` 设为 `SourceImage.Source.Width/Height`，强制网格等于真实显示图像尺寸；状态栏诊断同时显示「网格」和「源」尺寸。构建 **0 警告 0 错误**。运行请用 `_wpfout15\\Debug\\net8.0-windows\\GrayMatch.Wpf.exe`。

## 图像缩放/平移「从零重写」（ScrollViewer + LayoutTransform，2026-08-11）
- 用户前三轮增量修复都不彻底，直接要求「重新写图片放大缩小」。改用结构最可靠的 `ScrollViewer` + `Grid.LayoutTransform`(ScaleTransform `ImageScale`) 方案，彻底放弃之前 `Border`+`RenderTransform`(Scale+Translate) 的手动居中/平移数学（根因：人工居中永远对不齐 WPF 实际布局 → 底部被裁）。

  - `MainWindow.Zoom.cs`（局部类，主 xaml.cs 仍被沙箱误判二进制）整体重写：
    - 滚轮缩放：`e.GetPosition(ImageGrid)` 取**图像未缩放坐标**（GetPosition 返回已逆变换的本地坐标，居中/缩放无关，是光标锚定缩放的关键），`e.GetPosition(sv)` 取视口坐标；`sv.UpdateLayout()` 后 `ScrollToHorizontalOffset(pContent.X*newScale - pViewport.X)` 保持光标下点不动。
