## 修复 4x 耗时回归（用户："为什么耗时增加了4倍了，需要耗时降低"）
- 根因：上一版金字塔级联 `stepAt(k)=baseFineStep*2^k`，在 1° 终步下粗扫跑到 ~180 角度；小模板（32x18）被 cap 把 L 压到 1（0.5x 大粗图 × 多角度）= 4x 变慢。bench diagL 实测：OLD `L=1 coarseImg=600x600 step=2° ~180角度 coarsePxAng=6.5e7` vs NEW `L=2 coarseImg=300x300 step=15° ~24角度 coarsePxAng=2.2e6`。
- 修复方案（只改 `GrayModelNative/gray_model_native.cpp` 的 Pyramid cascade 段）：
  1. `L` 改由**图像尺寸**驱动（上限 6），收缩时按深度差异化：L>=3 要求粗模板短边 >=6px，L=2 允许 >=4px。这样 70x104 中等模板不会深到只剩 4x7px（导致 60° 在粗层丢失），32x18 小模板仍能保留 L=2 的加速。
  2. 最粗层固定粗角度步 **15°**；
  3. **渐进式逐层角度细化** k=L-1..1，`stepAt(k)=15°/2^(L-k)` 逐级减半把角度钉死（这是修复精度的关键，固定 15° 粗步在极小粗图上给错种子、±9° 细扫带救不回）；
  4. 最后复用 legacy 0.35x 窗口细扫（seed 来自细化结果），全空退全分辨率兜底。
- 重建：`touch gray_model_native.cpp && ninja` 成功（仅 C4819 无害警告），DLL 43520→**46592** 字节。bench 复测：
  - Test1 800x600 4 目标：legacy 18.4ms / pyramid=4 **4.6ms**（~4x），4/4、angErr 1.0°、框 120x80、score 0.92。
  - Test2 900x600 全扫：pyramid 1..4 ≈8.0ms（legacy 同场景 ~18.4ms）。
  - Test3 1600x1200 120x80 大图：legacy 135ms / pyramid **30ms**（~4.5x 加速），4/4。
  - Test4 小模板 32x18（4x 回归触发）：legacy 118ms / pyramid **104ms**（仍快于 legacy，无 4x 变慢）。
  - 旋转数字图（`图片1300x1000.png`，70x104 模板，18 个「2」0°~60°）：thr=0.30 时 pyramid 有 6 个低分假阳性；**thr=0.40 及以上 legacy 与 pyramid 均干净 18/18**，pyramid=4 约 18ms（legacy 30ms）。
- 结论：4x 回归消除，金字塔在 synthetic 和真实旋转数字图上都比 legacy 快且精度一致；稀疏/细笔画图案建议 NCC 阈值 ≥0.40。C# 端 `MatcherTests` 仍须用户正常环境跑。

## 修复"选金字塔层级后耗时不变"（用户："为什么选择金字塔级数之后耗时没有变化的"）
- 根因：`gray_model_native.cpp` 的 `match()` 算金字塔深度 `L` 时，多了一个 `while (L < 6 && ((minSrcDim >> (L + 1)) >= 64)) ++L;` 的"按图像尺寸向上生长"循环——把 L 推到图像允许的最大深度，又被模板尺寸上限拉回同一值。结果对 1339x1038 图+70x108 模板，`pyramidLevels`=1/2/3/4 全算出 **L=3**，耗时一致；只有选 0（走旧两遍分支）才不同。C# 侧参数传递正确（P/Invoke 签名与 C API 一致），问题纯在 native 的 L 计算。
- 修复：去掉"向上生长"循环，`L` 直接由 `pyramidLevels` 驱动（即粗层数量），仅在粗模板/粗图太小（NCC 不可靠）时向下收缩；逻辑与已验证的 standalone `chooseDepth` 一致。
- 附带坑：该 native.cpp 有中文注释，按 GBK(936) 读会 C4819 误把注释里的 `L` 当代码 token → 编译失败。→ CMakeLists 加 `/utf-8`；并显式 `#include <omp.h>`（启用 `/openmp` 后不再依赖隐式声明，否则 `omp_in_parallel` 报 C3861）。最终用 `cl /openmp /utf-8 /LD ...` 直接编出 DLL（build-ninja7 的 CMake 重配没刷新 flags，改为直编更稳）。
- 验证：`pyr_level_bench.cpp`（链接 GrayModelNative.lib，真实数字图 1339x1038，范围 -5~65，thr=0.40）结果 —— pyramid=0 57.4ms / 1 26.2ms / 2 13.1ms / 4 6.5ms，均 18/18 检出。层级现在明显改变耗时。
- 已 commit `9f5d961`。WPF 重新 `dotnet build` 后 `CopyNativeDeps` 已同步新 DLL（160768 字节 10:43，含 /openmp）到 `GrayMatch.Wpf/bin/Debug/net8.0-windows/`
