# 2026-08-14

## 「其他电脑提示找不到 GrayModelNative.dll」根因与修复
- 根因：GrayModelNative.dll 依赖 **VC++ 2022 运行库**（dumpbin 实测导入 MSVCP140 / VCRUNTIME140 / VCRUNTIME140_1；opencv_world480.dll 还依赖 CONCRT140）。本机因装了 VS 有这些运行库；其他电脑没装 VC++ 可再发行包 → 加载 GrayModelNative.dll 失败，被报成「找不到 DLL」。
- 修复（两个 csproj 的 `CopyNativeDeps` 都改）：
  - 自动定位 VS 2022 Redist（`C:\Program Files\Microsoft Visual Studio\2022\{Community|Professional|Enterprise}\VC\Redist\MSVC` 或 BuildTools），用通配 `$(_VsRedistRoot)\*\x64\Microsoft.VC143.CRT\*.dll` + `...\Microsoft.VC143.OpenMP\vcomp140.dll` 把 VC 运行库打进输出目录（自包含，目标机无需装任何东西）。
  - 注意 MSBuild 坑：`Include` 通配**只匹配文件不匹配目录**，所以 `...\*\...\Microsoft.VC143.CRT`（以目录结尾）解析为空；必须在末尾带 `*.dll` 文件通配。
  - 同时把两个项目的 native DLL 统一指向 `build-ninja9`（WinForms csproj 之前还指向旧的 `build-ninja7`，那是 8 参数版，会与 C# 9 参数 gm_match 签名冲突 → 崩；已修正，并把 WinForms bin 里 160768 字节的旧 DLL 替换成 46080 的 ninja9）。
- 增强 `RotatedTemplateMatcher.Match()`：首个 native 调用包了 `DllNotFoundException`（中文提示缺哪些 DLL、要放一起拷贝）/ `BadImageFormatException`（提示 32/64 位不匹配、需 x64）。
- 验证：`dotnet build GrayMatch.Wpf ... /t:Rebuild` → 0 警告 0 错误；输出目录已含 GrayModelNative.dll、opencv_world480.dll、vcruntime140(_1/_threads).dll、msvcp140(_1/_2/_atomic_wait/_codecvt_ids).dll、concrt140.dll、vcomp140.dll。已同步到 WPF 默认 bin 与 WinForms bin。
- 部署须知：把**整个**输出文件夹（`bin\Debug\net8.0-windows` 或发布目录）一起拷到目标机运行；目标机需 64 位 Windows。
